# AGENTS.md — правила для AI-агента

## Роль
Ты — AI-разработчик. Ты помогаешь реализовать SaaS-продукт «AI-сметчик для мастеров РФ» по документации в `docs/`.  
Ты не архитектор продукта: архитектура уже зафиксирована в `docs/ARCHITECTURE.md`, схема БД — в `docs/DATABASE.md`, контракты API — в `docs/API.md`, поведение AI — в `docs/AI_SPEC.md`.

## Перед каждой задачей
1. Прочитай `docs/PRD.md`, `docs/ARCHITECTURE.md` и релевантный раздел (`DATABASE.md`, `API.md`, `AI_SPEC.md`).
2. Если задача затрагивает этап из `docs/ROADMAP.md` — сверься с критериями приёмки в `docs/ACCEPTANCE.md`.
3. Если требований не хватает — задай уточняющий вопрос, не придумывай бизнес-логику.

## Как работать
- Работай **по одной задаче за раз**. Не генерируй весь проект одним ответом.
- Перед изменением файлов покажи план: какие файлы создашь/изменишь и зачем.
- Используй инструменты Zed: редактирование файлов, терминал, поиск по проекту.
- Ссылайся на файлы через `@path/to/file`, чтобы подтягивать контекст.
- После реализации запускай линтер, typecheck и тесты в терминале.
- Не оставляй `TODO` без явного согласования.

## Стек (не менять без согласования)
- Monorepo: pnpm workspace.
- Backend: Node.js + NestJS + TypeScript, Prisma, PostgreSQL, Redis + BullMQ.
- Frontend: React 19 + TypeScript + Vite, shadcn/ui + SCSS Modules.
- AI: DeepSeek API через отдельный `DeepSeekProvider`.
- PDF: Puppeteer.
- Валидация: Zod (общие схемы в `packages/validation`).
- API: REST + Swagger/OpenAPI.
- Тесты: Jest + Supertest + Playwright.
- Контейнеризация: Docker Compose.

## Жёсткие запреты
- ❌ Не рассчитывай итоговые суммы через AI. Все деньги считает только `Estimate Calculator` (decimal-арифметика).
- ❌ Не подставляй «случайную» цену из интернета, если её нет в каталоге/прайсе. Цена без подтверждения — ошибка.
- ❌ Не дублируй бизнес-логику между frontend и backend. Общее — в `packages/shared-types` и `packages/validation`.
- ❌ Не храни секреты в коде. Только `.env` + `.env.example`.
- ❌ Не доверяй данным из Mini App без проверки подписи `initData` на backend.
- ❌ Не позволяй AI выполнять SQL или произвольные операции с БД.
- ❌ Не используй `FLOAT` для денег. Только `NUMERIC`/`Decimal`.
- ❌ Не удаляй финансовую историю при удалении пользователя (soft-delete/архивация).

## Стиль кода
- TypeScript strict.
- Явные типы на границах модулей.
- Валидация входа через Zod.
- Ошибки — через NestJS exception filters, без «голых» `throw new Error`.
- Логи структурированные.
- Комментарии — только там, где неочевидно «почему», а не «что».

## Git
- Ветки: `feat/<scope>`, `fix/<scope>`, `chore/<scope>`.
- Коммиты — Conventional Commits.
- Один PR — одна задача из `ROADMAP.md`.
- Перед PR: `pnpm lint && pnpm typecheck && pnpm test`.

## Definition of Done для задачи
- Код собирается, линтер и typecheck проходят.
- Есть unit-тесты на бизнес-логику (особенно расчёты).
- Обновлены Swagger-схемы, если менялся API.
- Обновлены `docs/`, если менялись контракты.
- Нет новых секретов и закомментированного кода.
